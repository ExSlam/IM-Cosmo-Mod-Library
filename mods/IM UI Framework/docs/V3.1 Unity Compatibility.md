# IM UI Framework 3.1 Unity Compatibility

Idol Manager exposes an older/stripped Unity API surface through its shipped reference assemblies. Several helpers common in newer Unity releases are absent at compile time even though the underlying scene/UI data exists.

Version 3.1 centralizes those differences in `src/IMUiCompat.cs`:

- inactive child lookup uses `GetComponentsInChildren<T>(true)` and selects the first result instead of the unavailable singular `GetComponentInChildren<T>(true)` overload;
- loaded scene roots are discovered from loaded `Transform` objects and scene identity is read by reflection, avoiding newer `SceneManager.GetActiveScene`, `Scene.IsValid`, `Scene.GetRootGameObjects`, and `Scene.name` members;
- persistent UnityEvent targets are read through public methods when available, otherwise through Unity's serialized persistent-call fields;
- `ColorBlock` normal/pressed/selected/disabled states are written through their serialized backing fields because Idol Manager's UnityEngine.UI build exposes only `highlightedColor` as writable;
- TMP dropdown support is optional and runtime-detected because the game's TextMeshPro assembly has no `TMP_Dropdown` type.

These are implementation details. Existing v3 composable primitives, themes, scene templates, popup templates, month pager, producer-list scroll pattern, and Modern UI Pack bridges keep the same public API.
